# ADR-001: Adopt doctrine to govern this repo

## Context

This repo's governance grew by hand and every structure it invented has a
doctrine primitive behind it:

| here | primitive |
| --- | --- |
| `docs/ledger/` — 54 items, frozen ids, considered-and-rejected kept | ADR + memory + backlog + knowledge, **not 1:1** |
| `docs/status.md` **Now** / **Recent** | runtime state + slice phases |
| `docs/status.md` **Next** | backlog `issue`/`improvement`/`chore`/`idea` + slices |
| `docs/status.md` **Open** | split by the work-intake membership test: work intent → `risk`, epistemic claims → knowledge `assumption`/`question`/`constraint` |
| `docs/probes.md` — 1537 lines of figures | observations + knowledge `evidence` |
| CLAUDE.md *gotchas that have already cost time* | `doctrine memory record` |
| CLAUDE.md *architecture invariants* | POL / STD |
| `docs/contract-*.md` | SPEC / PRD + POL — they already split *by authority*, which is the POL-vs-SPEC distinction |
| `docs/plan-b/c/d/e` | SPEC, with order-of-work as slices |
| `HANDOVER.md` | `.doctrine/**/handover.md` |
| `docs/index.md` | `project-orientation.md` |

Two of these are actively bleeding. `status.md` conflated *work intent* with
*epistemic claims* in its **Open** section, which is exactly why that section
never shrank; and it regrew a 720-line reverse-chronological changelog once
already (`NOTES item 54`) because the commit messages stopped carrying the
session. doctrine's tier rule — *progress in runtime state, not authored files* —
makes item 54's failure structurally impossible.

The gotchas are the highest value per unit of effort: ~25 paragraphs in
CLAUDE.md, each a real cost already paid, and nothing can retrieve one.

The countervailing force is that oubliette **confines** doctrine. Being governed
by the thing you jail is not a mechanical collision — `target.nix`'s `statePaths`
are relative to the *guest's* checkout, so this repo's own `.doctrine/` is
invisible to the machinery — but it is a naming collision, because a slot's
`unit` and `purpose` fields already name doctrine's slices.

## Decision

We will adopt doctrine to govern this repo, on three terms.

**1. Routing is backlog-first.** Most capsule work runs straight off
`doctrine backlog` — issue / improvement / chore / risk / idea. **Larger programs
of work get a slice** and the full `/slice → /design → /plan → /execute →
/audit → /reconcile → /close` lifecycle. We will not open a slice for a one-file
fix, and we will not run a multi-phase program off a backlog item. This is
deliberately lighter than doctrine's own conduct: the full lifecycle for every
change is real overhead against how this repo has been driven, and the artifacts
that are bleeding are not the ones the lifecycle produces.

**2. The id spaces are strictly separate.** An `SL-`/`ADR-`/`REQ-` id in this
repo's `.doctrine/` means nothing in `~/dev/doctrine`'s corpus and vice versa; a
bare id is always this repo's. Nothing mechanical enforces this, so it is stated
in `project-orientation.md` where a cold agent reads it — the risk is a slot's
`unit`/`purpose`, which name *the confined project's* entities in this repo's
own records.

**3. We migrate forward, not backward.** The four homes with no doctrine
equivalent today — status, probes, gotchas, plans — are where all the pain is and
all of them are pure gain. The ledger is frozen rather than migrated; that is
ADR-002.

Order of work: fill `project-orientation.md`; retire `status.md`; CLAUDE.md
gotchas → memories; `probes.md` → observations; contracts and plans → SPEC/POL
last, because they are the least broken.

## Consequences

### Positive

- `status.md`'s **Open** section gets triaged by an actual membership test
  instead of accreting.
- ~25 gotchas become retrievable rather than being a wall of prose that only
  works if read in full.
- `probes.md` was flagged as legitimately unbounded; observations give growth a
  correct home.
- Item 54's failure mode — content accreting in the nearest file with no size
  bound — becomes structurally impossible for progress state.

### Negative

- Two governance systems coexist during the migration: the frozen ledger and
  `.doctrine/`. A reader must know which is closed.
- A second vocabulary in a repo that already uses doctrine's words for a
  different subject (`unit`, `purpose`).
- Backlog-first means no design artifact for work that later turns out to have
  needed one. Accepted: the escape hatch is opening a slice late.

### Neutral

- `docs/index.md` and `project-orientation.md` overlap; index stays as the
  question→file map for the `docs/` tree specifically.

## Verification

**VH** — the check is that `docs/status.md` is deleted and does not regrow, and
that no 55th ledger item appears. Both are readings of the tree, not tests.

Not exercised: nothing has run the lifecycle here yet. The routing rule in term 1
is a decision, not an observation — the first larger program of work is what
tests whether the backlog/slice boundary sits in the right place.
