# ADR-003: Evidence has one home, and it says what it does not prove

## Context

`probe/` is evidence, not scaffolding, and
[docs/probes.md](../../../docs/probes.md) is **the one place a probe's figures
and verdict are recorded** — everything else links there rather than restating a
number, because a figure copied into three documents is three figures the first
time one of them is edited. Seven of those figures are also `EVD` records, minted
only where another record load-bears on the number so the edge can be drawn; the
file says so in its own header, and says not to mint one for a figure nothing
points at.

That rule governs *this* repo's documents. It says nothing about the corpus next
door, and since `ADR-001` there are two.

**Evidence about oubliette was minted in doctrine's corpus before oubliette had
one**, and four records are still there:

| record | subject | how it cites here |
| --- | --- | --- |
| doctrine `EVD-018` | `probe/netns-boot.sh`, 9/9 | names the probe |
| doctrine `EVD-019` | `probe/freshness.sh`, 22/22 and the figures | names the probe |
| doctrine `EVD-020` | `probe/two-capsules.sh`, 28/28 and the figures | names the probe |
| doctrine `EVD-025` | host-integration and macOS portability cost | `../microvm-spike/docs/eval-macos.md`, `../microvm-spike/docs/plan-b-other-jails.md` |

`docs/probes.md`'s own probe table cites the first three by id, in the other
direction. So the graph already crosses, and nothing says which end owns a claim.

**The drift is not hypothetical; it has already happened.** doctrine's `EVD-019`
carries as its headline datum *8.31 s to a usable fresh capsule*. This corpus's
`EVD-002` is titled *Time-to-interactive is about two minutes, not 8.31 s*, and
says the two figures come from different runs and must not be quoted as one
result — an instance of `STD-001`'s **read back** rung. Both records are
`captured`. Neither links the other. `QUE-217` reads doctrine's side.

`EVD-025`'s citation form is the second half of the same problem: a relative path
out of one working tree into another resolves only from a directory neither repo
declares, and it names `microvm-spike`, which is this repo under its old
checkout name.

Meanwhile the probe corpus already carries two disciplines the `EVD` convention
never names, and they are the cheap version of what a conformance suite spends
its one-property-removed controls on:

- **Both directions.** `probe/harness.sh`'s `check <name> <ok|deny> <cmd…>` takes
  the expectation rather than a bare command, because **a denial-only test passes
  for the wrong reason**. `netns-egress.sh` asks the guest to reach a host the
  allowlist permits *and* one it does not, in both rounds.
- **What it deliberately does not prove.** Every probe header names the
  neighbouring question it refuses — `netns-egress.sh`'s says netns-boot's
  namespace has no upstream at all, *so a denial there would pass for the wrong
  reason*. `probes.md` carries the same at document scale: *What freshness.sh
  explicitly does not measure*, and *Still unproven*.

An `EVD` record has a `datum`, a `provenance` and a `confidence`. It has no place
to say which direction was asserted, or what the run deliberately leaves open.

## Decision

**Four clauses. The first two are the ownership rule, the third is what we do
about the records that predate it, and the fourth carries the probe conventions
up into the evidence convention.**

### 1. Oubliette owns evidence about oubliette's mechanism

Any observation whose subject is **this repo's machinery** — a probe run, a
figure taken off this host, a refusal exercised here, a cost of the confinement
itself — is minted in **this** corpus. doctrine cites it across **by id** and
does not re-mint it.

The test is *what is the subject*, not *who ran it* and not *who wants the
answer*. doctrine wanting a number is the ordinary case and is what citation is
for.

### 2. Doctrine keeps evidence whose subject is doctrine's own choice

A comparison between confinement shapes, an adoption cost, a portability
assessment, a selection between two tiers — the subject is **doctrine's
selection**, not oubliette's mechanism, even where the datum is read off this
repo. Those stay in doctrine's corpus. `EVD-025` is the type case and is
correctly placed.

Such a record cites this repo **by entity id and by repo-relative path**
(`probe/netns-boot.sh`, `docs/eval-macos.md`), never by a relative path that
climbs out of a working tree, and never by the `microvm-spike` checkout name.

### 3. The four existing records are not migrated

Same argument as `ADR-002`, one corpus over: a record's value is that it survived
contact with the run that produced it, and a re-mint is a fresh claim wearing an
old record's clothes. `EVD-018`, `EVD-019`, `EVD-020` and `EVD-025` stay in
doctrine's corpus, and `docs/probes.md` goes on citing the first three by id.

**What is owed is not a migration but a dispute made visible.** Where this corpus
already contradicts one of them — `EVD-002` against `EVD-019`'s headline — the
contradiction is stated on **both** records, and doctrine's is left standing with
its dispute named rather than silently corrected here and read stale there.

It is stated in **prose**, because the edge is not authorable:

```
$ doctrine link EVD-002 disputes EVD-019
Error: `EVD-019` does not resolve to an entity
  (no EVD-019 at …/oubliette/.doctrine/knowledge/evidence/019)
```

A relation resolves within one corpus. A cross-corpus citation is therefore a
sentence naming the other repo and the id, and this ADR does not pretend
otherwise — an ADR that prescribes a command that refuses is a rule nobody can
follow. What that costs is the whole graph half of the citation: nothing
enumerates what disputes what across the boundary, and `doctrine backlinks` sees
none of it.

### 4. A probe's two disciplines are evidence disciplines

Named here so they apply to any record in either corpus, not only to a `.sh` file
in `probe/`:

- **Assert both directions.** A record that only establishes the denial, or only
  the success, states which half it has and does not claim the other. A refusal
  observed without the matching admission is one observation, not two.
- **Say what you deliberately do not prove.** Every `EVD` minted from here on
  carries a **Not established** line — the neighbouring question the run refuses,
  and why refusing it is right. `EVD-008` was written this way before this ADR
  and is the shape.

Not backfilled. The line is added to an older record when it is next touched for
another reason.

## Consequences

### Positive

- One home per claim, so a figure has one place to be edited and one place to go
  stale. This is `probes.md`'s own rule, extended past the repo boundary it was
  silent about.
- `QUE-217` and anything else reading across gets an id that resolves, rather
  than a path built from somebody's directory layout.
- The `EVD` record grows the one field its subject matter has always needed: an
  evidence corpus that cannot say what it does not cover is a corpus whose gaps
  are invisible, which is `STD-001`'s whole argument one level up.

### Negative

- **Two corpora and a rule that is prose.** Nothing mechanically refuses a
  doctrine `EVD` whose subject is a probe in this repo; the check is a human
  reading clause 1. See *Verification*.
- The four grandfathered records make the rule read as *mostly*, and anyone
  arriving at `EVD-019` from doctrine's side still finds the 8.31 s headline
  first, dispute edge or not.
- **A cross-corpus citation is prose, so it is invisible to the graph.**
  `doctrine link` will not take a target in another corpus, so `backlinks`,
  `relation census` and every reachability question stop at the repo boundary.
  The rule this ADR sets is therefore enforceable only by reading.
- Clause 2's boundary is a judgement. *A cost of the confinement itself* and *an
  adoption cost of choosing it* are close enough that a record could be argued
  either way; the tie-break is which repo would have to change if the claim were
  wrong.

### Neutral

- `docs/probes.md` is unchanged as the source of figures. This ADR is about which
  *corpus* mints a record, not about where a number lives — the number lives in
  `probes.md` either way, and the record cites the section.
- No id moves. Both corpora keep their own `EVD` sequence, which already overlap
  in number and never in meaning.

## Verification

**Honest rung, `STD-001`: this is `build`.** It is written down and nothing runs
it.

- Clause 1/2 ownership: **unenforced.** No tool sees both corpora. A check is
  possible — grep doctrine's `EVD` bodies for `probe/`, `capsule-`, and this
  repo's paths, and report any record not covered by clause 2 — but it would live
  in doctrine and nothing in this repo can run it.
- Clause 2's citation form: **unenforced**, and the cheap half is mechanical — a
  relative path containing `../microvm-spike` in either corpus is always wrong
  now.
- Clause 3's dispute: **prose only**, and not because nobody typed the command —
  `doctrine link` refuses a target outside its own corpus, so the edge does not
  exist to be authored. Shown above.
- Clause 4's *Not established* line: **unenforced**, by choice. A required field
  would be filled with "nothing" the first time it is inconvenient, which is
  worse than an absent one.

Two things would make this real and neither exists: a cross-corpus lint for
clause 1, and a cross-corpus relation for clause 3. Recorded as owed rather than
claimed.
