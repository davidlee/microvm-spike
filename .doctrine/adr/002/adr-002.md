# ADR-002: The ledger is a closed archive

## Context

`docs/ledger/` holds 54 items across 8078 lines — one file per item
(`NNN-slug.md`), ids frozen and append-only, `proposed → accepted → superseded`
carried in prose, rejected alternatives kept. It is already ~90% of what
`doctrine adr` gives. What it lacks is precisely the **derived index**: the
index is hand-maintained, which is where it broke — `NOTES item 15`'s kind-3
ratchet is unrepresentable once nobody writes the row.

The hazard is the citation graph, and it is invisible from inside doctrine:

- **238** `NOTES item N` citations across **43** source files (`*.nix`, `*.sh`,
  the justfile), where the citation is the *only* record of why a line is shaped
  as it is.
- **135** more in markdown.
- **231** relative links of the form `ledger/NNN-slug.md`.

Renumbering breaks all of them, and it cannot be a clean `sed`, because the
mapping is not 1:1 — a ledger item that becomes a `memory` or a `risk` has no
ADR id to rewrite to. A full migration therefore means two id spaces *and* ~370
edited citations *and* rewriting 8078 lines of reasoning whose entire value is
that they are checkable against the code they describe. The value of a ledger
item is that it survived contact; a rewrite is a fresh claim wearing an old
item's clothes.

## Decision

We will **freeze `docs/ledger/` at item 54 and treat it as a closed archive.**

- **No item 55.** The file set stops growing, so the accretion stops
  immediately.
- **`NOTES item N` remains a valid citation form forever**, and is documented as
  such in `project-orientation.md`. It is an id, not a path: moving or renaming a
  file changes nothing about how it is cited.
- **Items may still be resolved in place** — an item's own `*State:*` header may
  be updated when the world moves under it. Never renumbered, never deleted.
- **New decisions go to `doctrine adr new`** from day one; durable gotchas to
  `doctrine memory record`; latent work to `doctrine backlog new`; epistemic
  claims to `doctrine knowledge new`.
- **We do not backfill.** The archive is not migrated, item by item or in bulk.

## Consequences

### Positive

- Zero broken citations. No big-bang.
- The reasoning stays checkable against the code it describes, because it is
  untouched.
- Growth stops at the point of decision rather than at the point of cleanup.

### Negative

- Two decision homes coexist permanently: an archive and `.doctrine/adr/`.
  Anyone looking for "why is it like this" must check both, and only
  `project-orientation.md` says so.
- The archive's index stays hand-maintained and stays stale — accepted, because
  a frozen index has a bounded amount of staleness.
- An archived item that a new ADR supersedes cannot carry a `superseded_by`
  edge, since it is not an entity. The new ADR must cite the item in prose.

### Neutral

- The hand-rolled evidence ladder in `NOTES item 1` — build / run / start /
  trigger / take / exercise / compare / reach / read back — is finer than
  doctrine's three verification modes (VT / VA / VH) and is not replaced by them.
  It is a candidate STD in its own right: *how to pick a mode, and what evidence
  each rung actually buys*. That is the piece this repo earned that doctrine
  could take back.

## Verification

**VH** — no `docs/ledger/055-*.md` exists, and `grep -c 'NOTES item'` over the
source tree does not fall. Both are readings of the tree.

Not exercised: nothing enforces the freeze. A cold agent that has not read
`project-orientation.md` will write item 55, because the ledger's own
`index.md` still reads as a live convention. A follow-up edit to that index and
to `CLAUDE.md` is what closes the gap; until then this ADR is a claim on the
reader, not a control.
