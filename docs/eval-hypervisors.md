- Keep microvm.nix. hypervisor = "…" is a one-word switch across 8 runners with a NixOS-declarative guest and a generated store image. Nothing else offers that.
- firecracker's whole cost is "no shares": bootstrap tarball, secrets problem, read-only store, no nix develop/nix build in guest. 
- Worth trialling: cloud-hypervisor. Rust VMM, runner passes --seccomp true and --watchdog, KVM-only, gains virtiofs shares (secrets by ro-bind, no tarball) and balloon (16 GiB stops being pinned). Cost: virtiofsd is an extra host daemon speaking guest-controlled protocol, plus a somewhat larger device model. Policy — no default route, proxy-only egress, host-side ref guard — is untouched. Better ergonomics, marginally more surface, same isolation class.
- crosvm is the interesting outlier: shares and --pivot-root, with per-device minijail sandboxing built in — the only runner where jailer-grade confinement is free. nixpkgs maintenance is spottier; would need verifying before trusting.
- qemu is the only runner honouring microvm.user (-run-with user=), but it's the biggest surface, and its user-mode net would void your egress control. No.
- Firecracker direct + jailer: don't. jailer wants everything inside a chroot; the generated config JSON is absolute /nix/store paths, so you'd pre-populate a chroot with the closure and end up reimplementing microvm.nix badly. Dedicated uid + cgroups gets ~80% of jailer for ~5% of the work.
- Not worth trialling: Kata (k8s-shaped), libkrun/krunvm (OCI-shaped, no NixOS guest), systemd-vmspawn (no declarative guest, wants shares), alioth/stratovirt (immature).
